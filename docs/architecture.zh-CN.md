# 架构：企业内网文件平台

## 系统边界

- 产品边界包括一个内网 Web 应用，用于文件管理、部门协作、公共知识发布、元数据搜索、Office 在线编辑、版本恢复、回收站恢复和审计查看。
- 运维边界包括超级管理员对账号管理、权限管理、导入任务、配额管理、审计检查以及未来 AI 启用控制的操作流程。
- 文件、元数据、权限、版本、回收站状态和审计记录都属于本仓库预期的系统边界。
- 外部 AI 提供方在 MVP 运行边界之外，并且默认保持关闭。
- MVP 中选定的内部编辑器边界为自托管 ONLYOFFICE Docs Enterprise，而不是公网外部依赖。

## 建议的仓库结构

- `docs/` 用于存放 brief、架构、操作说明和双语规划文档
- `specs/` 用于存放面向实现的持久化规格及其中文伴随文件
- `apps/web/` 用于存放用户端 Web 应用和管理员界面
- `apps/api/` 用于存放内部 API 服务，负责认证、空间、文件、权限、搜索和审计接口
- `packages/domain/` 用于存放空间、权限、版本、回收站和发布规则等共享业务逻辑
- `packages/storage/` 用于存放文件内容存储、版本存储和导入工具
- `packages/search/` 用于存放元数据索引和权限感知搜索
- `packages/editor/` 用于存放 ONLYOFFICE Docs Enterprise 集成、文件锁处理和保存回调
- `packages/audit/` 用于存放审计事件模型和查询辅助逻辑
- `workers/` 用于存放后台任务，例如锁清理、回收站清理、版本裁剪、配额刷新和导入执行
- `deploy/` 用于存放 Docker Compose 和环境相关部署资产
- `tests/` 用于存放按领域、API 和端到端拆分的自动化测试

## 核心组件

- 界面层：
  - 面向用户的文件管理界面，用于浏览个人空间、部门空间和公共知识库
  - 面向管理员的界面，用于管理账号、权限、导入、配额、审计日志和发布者授权
  - 元数据搜索界面，用于按权限范围展示过滤后的结果
- 领域逻辑：
  - 身份和会话规则
  - 空间与文件夹归属规则
  - 权限判断和共享约束
  - 公共知识发布规则
  - 公共知识分类和归档内容可见性规则
  - 版本历史和回收站规则
  - 受支持 Office 文件的编辑锁规则
- 持久化或外部集成：
  - 用于保存用户、部门、空间、文件夹、文件、版本、权限、锁、导入和审计等信息的元数据数据库
  - 基于服务器挂载卷或其他内网存储层的文件内容存储
  - 仅对授权内容生效的元数据搜索索引或查询层
  - 面向受支持可编辑文件类型的自托管 ONLYOFFICE Docs Enterprise 集成
  - 在 MVP 中默认关闭的未来 AI 提供方适配层
- 后台任务或定时任务：
  - 导入执行
  - 编辑锁过期清理
  - 回收站过期清理
  - 版本保留裁剪
  - 配额重算
  - 审计保留清理

## 核心流程

1. 用户请求进入 Web 界面，并通过应用会话层完成认证。
2. 应用在列出、搜索、下载、编辑、恢复或发布内容之前，先解析用户角色、空间范围和显式授权。
3. 文件操作经过领域规则处理，区分个人空间、部门空间和公共知识库的行为差异。
4. 对受支持文件的在线编辑会先获取单文档编辑锁，再通过编辑器集成边界保存，并生成版本历史条目。
5. 删除操作先把内容送入回收站，恢复操作则尽量把内容放回原始位置和原始归属上下文。
6. 导入任务将预先整理好的本地目录映射到目标空间，并输出校验和执行报告。
7. 审计事件会为关键的认证、授权、共享、发布、恢复和破坏性操作写入记录。

## 集成点

- 认证与鉴权：
  - 内部用户名密码登录
  - 会话管理
  - 针对每条内容访问路径执行角色和授权判断
- 数据存储：
  - 保存用户、部门、空间、文件夹、文件、版本、权限、锁、导入、配额和审计记录的关系型元数据存储
  - 保存二进制文件和版本内容的内网文件存储
- 队列或工作系统：
  - 用于导入、清理、配额刷新和保留任务的内部 worker 执行机制
  - 如果单机设计足够，MVP 不要求引入外部队列
- 外部 API 或内部服务：
  - 面向 `docx`、`xlsx` 和 `pptx` 的自托管 ONLYOFFICE Docs Enterprise 服务，MVP 优先采用其原生集成模式，而不是以 WOPI 优先的设计
  - 用于后续显式启用 AI 的可选适配层，可对接本地模型或外部 API，但在 MVP 中保持关闭

## 安全与可靠性约束

- MVP 中任何路径都不应依赖外网访问。
- 浏览、搜索、下载、版本访问、恢复和发布动作之前都必须执行授权检查。
- 超级管理员虽然拥有系统管理权，但不应因此默认绕过私有内容可见性规则。
- 部门主管管理部门空间，但不继承员工个人空间访问权。
- 编辑锁状态必须可恢复、可审计，并能在会话过期或失败时被清理。
- 只有在版本历史和回收站行为完整实现后，删除语义才算完成。
- 配额必须反映当前文件、历史版本、回收站项目和辅助产物带来的真实存储压力。
- 默认配额基线为个人空间每个 `10GB`、部门空间默认每个 `50GB`、公共知识库 `200GB`，并额外保留至少 `300GB` 的未分配系统预留。
- 公共知识库内容应区分已发布内容和已归档内容，以便未来 AI 启用时优先读取更安全、更经过整理的资料。
- 已归档的公共知识内容应在普通用户的默认浏览和搜索视图中隐藏。
- 即使在单机部署中，备份和恢复路径也必须与主生产存储卷分开规划。

## 开放问题

- 当前 MVP 规划基线下已无阻塞性的架构问题。
- 部署阶段仍需完成编辑器许可采购，以及在首批导入盘点后微调部门级配额覆盖值。
