# 发布评估

## 目的

本文档用于记录在用户明确允许跳过 Phase 4 之后，当前已实现 V1 基线的发布信心和剩余风险。

## 评估日期

- 日期：2026-03-11
- 评估依据：
  - `docs/_codex/STATE.md` 中的实现状态
  - `docs/_codex/PROGRESS.md` 中的验证历史
  - `docs/release-readiness.md` 中的当前上线检查清单

## 当前结论

- 如果本次发布范围不包含真实的在线 Office 编辑，则当前基线可以用于内部试点或运维验证环境。
- 如果本次发布要求覆盖原始 V1 规划中的在线编辑能力，则当前状态还不能视为完整可发布。

## 已测试范围

以下范围已经有实现和直接验证证据：

- 工作区初始化、API 构建和 Web 构建
- Docker Compose 基线和健康检查接口
- 超级管理员登录与首次强制改密
- 部门创建和用户创建
- 空间浏览与目录导航
- 文件夹创建、改名、移动、删除到回收站和恢复
- 文件上传、下载、改名、移动、删除到回收站和恢复
- 共享授权、共享列表和撤销共享
- 权限感知的元数据搜索
- 版本列表、内容替换和版本恢复
- 配额汇总和占用统计
- 维护概览和配额刷新执行路径
- 公共知识分类列表、发布流程、条目列表和状态更新

## 未测试或仅部分测试的范围

以下范围仍未完成真实验证，或者目前只有骨架实现：

- 真实 ONLYOFFICE 编辑运行链路，包括文档打开、保存回调、锁竞争和强制解锁
- 面向真实部门数据集的自动化批量导入执行
- 长周期保留策略执行，包括回收站过期和版本裁剪
- 完整的浏览器端到端回归覆盖
- 发布级安全演练，例如多次登录失败行为和恢复演练

## 面向广泛发布的阻塞项

以下项目应视为更大范围生产发布前的阻塞项：

1. 如果发布承诺包含在线编辑，必须提供并验证真实的 ONLYOFFICE 文档服务器。
2. 必须替换或重置开发阶段种子账号，并确认生产密钥配置正确。
3. 必须确认目标服务器上的 PostgreSQL 和文件存储都映射到持久化存储。
4. 需要决定首轮数据导入是继续由运维手工执行，还是必须在上线前做成自动化。

## 剩余风险

- 在线编辑仍然是最大的未收口运行时依赖。
- 当前导入仍有一部分依赖人工步骤，首轮上线时运维误操作风险更高。
- 保留策略基础设施已经存在，但定时清理和长期验证仍未完成。
- 当前回归信心主要来自人工验证，而不是专门的自动化端到端测试套件。

## 建议的发布模式

### 选项 A：不带编辑器的试点发布

当目标是先让小范围内部用户验证身份、权限、存储流程、回收行为和公共知识发布时，建议使用这种模式。

必要条件：

- 试点范围明确排除在线编辑
- 初始内容导入按运维手册执行
- 在目标环境上完成 `docs/release-readiness.md` 清单

### 选项 B：带编辑器的正式发布

只有在 ONLYOFFICE 运行链路已配置并完成端到端验证后，才建议采用这种模式。

必要条件：

- 编辑会话可以正常打开
- 保存回调能正确写回内容
- 单编辑者锁行为已确认
- 强制解锁后的运维恢复路径已验证

## 建议的下一步动作

1. 先决定近期目标是内部试点还是更广泛的正式发布。
2. 如果在线编辑是必须项，恢复 Phase 4 并接入真实 ONLYOFFICE 服务。
3. 如果在线编辑暂时不是必须项，优先做自动化导入或更强的回归测试覆盖。
4. 在任何上线动作之前，先在目标环境执行 `docs/release-readiness.md` 清单。
