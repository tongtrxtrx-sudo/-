# 计划：V1 分阶段交付

## 目标

以小阶段方式交付 V1 企业内网文件平台，优先解决风险最高的区域：身份体系、权限边界、存储行为、生命周期控制和编辑器集成。每个阶段结束时系统都应保持可部署状态，并且不启动 AI 相关开发。

## 交付原则

- 先稳定身份、空间边界和权限判断，再加便利性功能。
- 版本历史、回收站、配额和审计属于核心产品行为，不是后补的打磨项。
- 在整个开发过程中，始终保持 MVP 可以部署在单台内网服务器上。
- 在文件标识、存储和版本契约稳定之前，不启动编辑器集成。
- V1 所有阶段都保持 AI 关闭。

## 阶段 1：基础设施与身份体系

### 目标

- 建立运行时骨架、部署骨架和核心数据模型。
- 交付基础身份、会话、角色和空间原语。
- 建立基础审计模型和存储抽象。

### 范围内

- `apps/`、`packages/`、`workers/`、`deploy/` 和 `tests/` 的仓库骨架
- Docker Compose 基线和环境变量接线
- 用户、部门、角色和空间实体
- 用户名密码登录
- 首次登录强制修改密码
- 账号状态处理，包括正常、锁定、禁用和必须修改初始密码
- 会话管理
- 核心审计事件模型
- 文件元数据模型和内网存储抽象

### 退出标准

- 用户可以登录、修改初始密码，并进入与角色相匹配的首页区域。
- 超级管理员可以创建、禁用和重置用户。
- 系统可以创建个人空间、部门空间和公共知识库空间记录。
- 登录、退出、重置密码和账号状态变更都会产生审计事件。
- Docker Compose 可以在本地启动基础服务。

## 阶段 2：空间、文件与权限

### 目标

- 交付核心文件管理行为和权限模型。
- 尽早把个人私有边界和部门协作边界锁定下来。

### 范围内

- 个人空间文件和文件夹 CRUD
- 带有协作区、发布区和归档区的部门空间目录树
- 公共知识库浏览界面
- 仅允许向指定用户显式共享
- 不允许再次转分享个人共享内容
- 权限判断中间层或共享领域规则层
- 文件上传、下载、重命名和移动
- 按文件名、路径、上传者和更新时间进行元数据搜索
- 部门成员在协作区之外默认只读

### 退出标准

- 个人内容默认私有。
- 共享的个人内容只对被点名的接收者可见。
- 部门成员可以浏览部门内容，但只能在协作区或被明确授权的位置编辑。
- 元数据搜索结果中不会出现未授权内容。
- 公共知识库内容仅按已定义的发布规则可见。

## 阶段 3：生命周期、配额与审计运维

### 目标

- 补齐破坏性操作的安全行为和保留策略。
- 在引入编辑器之前，让存储压力和审计能力先具备可运营性。

### 范围内

- 回收站移动与恢复行为
- 面向非编辑器内容变更路径的版本历史模型和恢复行为
- 可配置的配额模型
- 默认配额基线：
  - 个人空间每个 `10GB`
  - 部门空间默认每个 `50GB`
  - 公共知识库 `200GB`
  - 至少 `300GB` 的未分配系统预留
- 针对当前文件、版本和回收站项目的配额统计
- 回收站清理、版本裁剪、配额重算和审计保留的后台任务
- 超级管理员的审计查询视图
- 已归档内容默认对普通用户浏览和搜索隐藏

### 退出标准

- 删除内容会进入回收站，并能在保留期内恢复。
- 支持的文件更新路径可以列出并恢复版本历史。
- 配额可见且按实际占用生效。
- 超级管理员可以按用户、文件、事件类型和时间查询审计事件。
- 普通用户默认看不到已归档的公共知识内容。

## 阶段 4：在线编辑集成

### 目标

- 仅在存储和生命周期契约稳定后，再引入选定的编辑器集成。
- V1 保持单编辑者行为，不做多人实时协作。

### 范围内

- 自托管 ONLYOFFICE Docs Enterprise 集成
- 优先采用原生集成方式，而不是以 WOPI 优先的设计
- 单编辑者锁获取与释放
- 锁超时清理与强制解锁行为
- 保存回调处理
- 保存时生成新版本
- 锁定、解锁、强制解锁和保存的审计事件
- 对 `docx`、`xlsx` 和 `pptx` 的可编辑支持

### 退出标准

- 授权位置中的受支持 Office 文档可以被打开进行编辑。
- 当锁生效时，第二个用户只能以只读方式访问。
- 编辑器保存会生成新版本，并保持权限边界不变。
- 强制解锁只允许授权操作员执行，并被写入审计日志。

## 阶段 5：公共知识发布、导入与上线加固

### 目标

- 完成公共知识工作流和上线运维准备。
- 完成首批数据导入路径和发布前检查。

### 范围内

- 超级管理员和授权部门主管的公共知识发布
- 公共知识内容必填元数据
- 首版分类体系：
  - 制度流程
  - 模板表单
  - 培训资料
  - 产品资料
  - 项目案例
  - 常见问题
- 已归档状态处理和发布者筛选能力
- 一次性初始导入任务和导入报告
- 面向备份、保留任务和运维可观测性的部署加固
- 以 `docs/brief.md`、`specs/mvp.md` 和 `docs/architecture.md` 为基准的最终验收走查

### 退出标准

- 授权发布者可以带着必填元数据发布和更新公共知识条目。
- 已归档的公共知识默认对普通用户浏览和搜索隐藏，但授权操作员可通过显式筛选查看。
- 管理员可以从预先整理好的目录结构运行导入任务，并查看可执行的导入报告。
- MVP 可以在目标单机环境中部署，并具备清晰的运维假设说明。
- MVP 规格中的所有验收标准都被人工或自动化验证覆盖。

## 延后到 V1 之后

- 按部门启用 AI
- 全文索引
- 多人协同编辑
- 审计导出
- LDAP 和 SSO

## 建议的立即下一步

从阶段 1 开始，实现以下最小纵向切片：

- 用户账号生命周期
- 登录与首次改密
- 个人空间、部门空间和公共知识库的空间记录
- 核心审计事件接线
- Docker Compose 基线
