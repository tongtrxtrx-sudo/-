# 上线准备检查

## 目的

本文档定义当前 V1 实现基线的最小上线准备要求。

## 当前已包含范围

- 身份与账号生命周期
- 个人空间、部门空间和公共空间
- 文件上传、下载、改名、移动和共享
- 元数据搜索
- 回收站
- 版本历史基线
- 配额基线
- 公共知识元数据与发布基线

## 当前排除或延期范围

- 在没有配置文档服务器时的真实 ONLYOFFICE 运行验证
- 自动化批量导入任务
- 超出当前维护入口之外的保留清理执行
- AI 启用

## 上线检查清单

1. 确认目标环境的 `.env` 已正确配置。
2. 确认 `JWT_SECRET` 不再使用开发占位值。
3. 确认数据库和应用文件存储卷已映射到预期的持久化存储。
4. 确认 `API_PUBLIC_BASE_URL` 与目标环境一致。
5. 确认公共知识分类已经存在。
6. 确认开发阶段种子账号在上线前已替换或重置。
7. 确认管理员已经理解导入运行手册。
8. 确认超级管理员可以访问审计界面。
9. 确认默认配额基线适合目标环境。
10. 确认抽样文件的回收站和版本恢复行为正常。
11. 如果上线时包含 ONLYOFFICE，确认文档服务器地址和 JWT 配置已经验证完成。

## 最小验证命令

```powershell
npm run typecheck
npm run build
docker compose --env-file .env.example -f deploy/docker-compose.yml config
docker compose --env-file .env.example -f deploy/docker-compose.yml up -d --build
```

## 最小功能检查

- 以超级管理员登录
- 创建部门
- 创建用户
- 上传示例文件
- 共享示例文件或文件夹
- 搜索示例文件
- 删除并恢复示例文件
- 替换文件内容并恢复旧版本
- 发布一个公共知识示例条目

## 已知上线风险

- ONLYOFFICE 仍然是在线编辑真实验证所依赖的外部组件。
- 当前导入仍有一部分是人工操作。
- 保留清理的真实执行和调度还需要在后续生产加固中完成。
